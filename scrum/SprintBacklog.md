## 三、执行计划（How）

> **本区归 Developer 所有。** 细化 PBI、拆解任务、排执行顺序、记录进展，均由 Developer 在此进行，Sprint 期间自行更新；PO 与其他角色不在此区预设内容。

### 推进顺序与依赖

**结构先行，规格模板居中，表皮收尾**：PBI-15（结构重构，含 14-1 的 skill 三处写入）→ PBI-17+18（规格与模板）→ PBI-14（designer 重造 + 风格重构）→ PBI-16（描述互链收尾）→ 全量验证 → Review / Retrospective。

依赖理由：

- 15 定两内核最终结构，14-1 的「skill 三处写入」随 SKILL.md 重构一次完成，不单独改两遍；
- 17 的规格清单与 18 的模板挂在新结构上，先于 14/16 定稿避免返工；
- 14 的 designer 重造与风格重构依赖 15 的模式/机制定稿；
- 16 描述两内核最终形态，收尾做。

### 工作项分解（每项 ≤1 天）

#### PBI-15 融合重构（最大块；含 14-1 的 skill 三处写入）

- 15-A 定案核对与落文准备：机制点与四开放点已在产品日志定案，落进重构稿
- 15-B design-kernel SKILL.md 重构：融合设计冲刺、讲清设计冲刺是什么、五天法清零（含 decider 归 PO）、原型原则写入三处（describe / 第一节 / 对应章节）
- 15-C DesignSprint/ 子目录处置（去留定论后执行；内容融入或保留为引用）
- 15-D scrum-kernel SKILL.md 重构：清晰可读、与 design-kernel 同构对齐（以盘上最新版为基准——Roles 已收为 PO/SM/Developers）
- 15-E 无死链扫描 + plugin-validator

#### PBI-17 + PBI-18 规格与模板（同簇执行）

- 17/18-A 关键文档/元件规格清单 + 模板清单草案 → PO 确认
- 17-B review 产出规格成文（第一份落地规格）
- 18-B design 侧模板落盘
- 18-C scrum 侧模板落盘
- 18-D 与 skill 接线（SKILL.md ≤2 跳可达）+ PO 逐份验收

#### PBI-14 快原则与 output-styles

- 14-A designer 重造（设计阶段专有定位，弃旧版「AI agent 设计师」内容）
- 14-B developer / scrum-master 重构（抄书合规路径：方法流程可录、不逐字大段）
- 14-C description 触发条件式 + 区分度复查（对照 CLAUDE.md 规约）（2026-08-31：两 describe 已重写互链，14-1 三处写入同时落盘；复查随 skill-reviewer）

#### PBI-16 描述互链（收尾）

- 16-A 两 kernel 描述深度优化互链（2026-08-31 完成）+ plugin.json 元数据同步（已查：展示用元数据已覆盖双内核，无需改）

#### 收尾

- 全量验证：plugin-validator + skill-reviewer + 无死链
- Sprint Review（PO 检视 Increment）→ Retrospective → 蒸馏闭环（四段式日志 + 记忆档案 + SprintBacklog 归西）
