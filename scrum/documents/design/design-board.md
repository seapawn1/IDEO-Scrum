设计目标：**一眼就知道**——看板挂在 PO 的屏上，好看、形象；PO 隔一阵瞄一眼，就知道项目走到哪、每条线在做什么；不用再问 AI、翻 git、读日志，看着就想一直挂着。

## 1. Empathize

**挑战**：Sprint 19 的看板第 1 版 PO 说「作为第1版来说，我觉得还不错」，但要「改得更漂亮一些，现在这个太丑了」；这次 PO 要深度参与（「上次也做原型了……相当于是你来看的嘛……我也没有参与……这次我打算深度参与一下」）。

现状与痛点：Mermaid 画的架构图「蛮丑的」，靠 CDN；路线图照抄日志、没概括；只有一版，PO 没参与。三条反馈：电脑全屏和手机屏都要适配；用前端设计（frontend-design 技能）的做法重做；只概括，架构图不能太复杂，细节去看日志。

## 2. Define

**地图**（画想要的体验，PBI-70 第 4 条）：早上瞄一眼屏 → 看见产品圆圈和没做完的条目 → 看见每条流进哪个冲刺或设计 → 点一下看卡片 → 知道走到哪、每条线在做什么 → 回到手头的事。

**HMW**：怎样让一张图在一瞥里说清产品、条目、冲刺、设计的关系；怎样让「在冲刺里」的条目一眼分得出来；怎样让手机上也能读完一张卡；怎样让页面不用联网、每次生成都一样好看。（设计问题 1～6 见下。）

## 3. Ideate

**PO 的方案**（定案，取代 Master 先定的「项目流水线」——PO：「你这个确实设计得不错……但是跟我想的还是不一样……我觉得你这个方案没有我的好」；风格沿用：「你的这个风格我觉得还是蛮不错的」）：总览流向图 + 三层卡片。

- 总览：一张竖着的流向图。产品是圆圈，「分出去外面所有东西」；分出没做完的条目（一列方块）；条目流进冲刺，也可能流进设计；几条线可以并行；点节点跳卡片，有返回。
- 每张卡三层：产品＝两个承诺 / 航线式架构（「一定要简练」）/ 没做完的条目；冲刺＝Sprint Goal / 条目往前走 / How 竖着排的小节点；设计＝设计目标 / 地图主线 / 方案小故事。

Master 照调研加的：连线照 GitHub Actions 的依赖线；点条目亮去向；条目按在冲刺里 → 待选 → 以后由近到远、越远越淡（Now-Next-Later）；全页只有「现在」一种亮色；架构画成一条线路、标出冲刺停在哪（地铁线路图）；电脑左总览右卡片（先概括后下钻）；手机缩窄、卡片占满屏。

PO 看第 2 版后的修改：路线不要画五个阶段——「那种都是众所周知的呀，你用它没有用的……冲刺的，那你就是几个 [PBI] 这样排列，然后一个箭头往前走……设计的，那你可能就是一个地图」；How 只分做完和没做完。

## 4. Prototype

故事板（静态画面，数据是本仓库 2026-11-14 的样子），三版：v1 Master 的项目流水线（被取代）；v2 八帧，PO 的方案（总览 → 点亮去向 → 冲刺卡 → 设计卡 → 产品卡 → 电脑 → 手机 → 白纸）；v3 照 PO 的修改（路线改成条目和地图，How 只分做完没做完）。PO 说不用做真网页（「根本都不需要把那个网页做出来」）。

## 5. Test

**标准**（事先写）：PO 看完故事板逐帧说感觉；设计问题 6 个，PO 说「行」算、说不行算否、要先看真页面算还没定；只由 PO 测（看板只给他用）。

**结果**：第 1 版风格认可但条目与冲刺的关系没画出来，PO 换方案；第 2 版「相当好，相当好」，只有路线画错；第 3 版「原型做得不错……基本上没问题，我们就过掉了」。六个问题里 1、3 留到真页面验（隔着距离看、字号），2、4、5、6 在版式层面为是。

**结论流向**：Sprint 20 的 68-b 照第 3 版做模板（固定页面 + 一块数据，只读、离线）；`board-log.md` 跟着改（不画五阶段、第一版不上「在等 PO」、架构与地图是概括）；PBI-68 的用户故事把「拿它拍板」改成「找回方位」。

**做法教训**（留给 Sprint 20 的 Retro）：共情、定义由 PO 和 Master 当面定，比交给一个新会话快、也准；原型用静态故事板就够，PO 看一眼就能指出错处；两个画方案的子代理拿到同一份「模式小结」，方案趋同成一个思路，分材料时要连小结一起分开。
