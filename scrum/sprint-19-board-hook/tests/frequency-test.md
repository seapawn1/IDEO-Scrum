## 6. 判定

先定归一化 `norm(s)`：转小写，只留字母、数字、汉字，其余（空白、标点、Markdown 符号、引号）全丢掉。每个探针取那一轮的 `result` 文本（该轮最后的回答）判：

**行为栏**（过线只看这一栏）

- `引用当前`：`norm(回答)` 包含 `norm(当前目标整格原文)`——P1、P2 的当前目标都是 v2 的整格。
- `过期`：`norm(回答)` 包含 `norm(v1 整格原文)`，或包含 `norm("失败的行单独记下来")`。
- `查日志`：这一轮里模型用 Read、Grep 读过 `SprintBacklog.md`（从流里该轮的 tool_use 看）。只记数，不进过线。

**内容栏**（只汇报，不进过线）

- P1 按 v2 应当不选入（「本冲刺不碰错误清单」）；P2 按 v2 应当选入（「选择要导出的列」正是 v2 的内容）。脚本按否定词、肯定词初判，每一条人工复核，改判写明理由。

判定脚本先拿两份已知结果自测：一份写进 v2 整格原文的、一份只写 v1 的，两份都判对了才用。

## 7. 过线与选定（跑之前定）

- **仪器有效**：A2 的 P1、P2 的 `引用当前` 各 ≥ 2/3。否则测不了——先查夹具和判定脚本，不算结果，不去动过线。
- **臂过线**：P1 与 P2 的 `引用当前` 各 ≥ 2/3，且 `过期` 各 ≤ 1/3。
- **选定**：在过线的臂里，选整场注入次数最少的（次数从流里我们的 hook 的非空输出数；并列时按 A1 < A4 < A3 < A2 取前者）。
- **A0 也过线**：说明模型自己会去读日志，注入没有可测的好处；仍照 PO 的决定带 SessionStart 一档，UserPromptSubmit 选最省的过线臂，并如实记「测不出」。
- **没有任何臂过线**：报 Master，不自己改标准。
- 报每次注入多少 token：同一个提示在 A0 与 A2 下各跑 3 次，取 `usage` 里输入 token（`input_tokens` 加两项缓存）之差，除以注入的次数。

## 8. 测法与通道

- 通道照 CLAUDE.md「回归测试」与 PO 2026-11-13 的规矩：`claude-magpie.cmd -p`（Git Bash 里写 `claude-magpie.cmd`），`--plugin-dir` 指向本分支的 `plugins/ideo-scrum`，`--model haiku` 实际跑的是 magpie 的便宜模型，汇总里写「magpie 的便宜模型，非 Haiku」，不写模型名和提供方。
- 工具只开 `Read,Grep,Glob`（`--tools` 与 `--allowedTools` 同给），不给 Bash 和 PowerShell。
- 子进程要设 `CLAUDE_CODE_GIT_BASH_PATH`（指向本机 Git 的 `usr\bin\bash.exe`），让 hook 走 Git Bash，和多数用户一致。
- 每次运行：全新的空工作目录、全新的空 `TEMP`、`TMP`；`--output-format stream-json --verbose --include-hook-events`；原始流放仓库外。
- 顺序：先冒烟一次（最简单的调用：模型在、读文件正常、hook 在流里出现、`/compact` 在这条通道里可用），估出一次完整运行的成本，报 Master，再正式跑五个臂各 3 次。

## 9. 规模参数（冒烟后可调）与不可调的

- 可调：填充的轮数与题面、`N`（现为 5）、夹具文件的长短、并行跑几个。调了写明原因，并在正式跑之前再提交一次本文件。

## 11. 已知局限

- 三次一档，只分得出大差别；一次之差不算差别。
- 会话只有十四个提示加一次压缩，够不上「很长」：模型对早先上下文的注意力衰减测不出，测的是「过期」和「压缩」两种已知的丢失方式。
- 换的是 magpie 的便宜模型，不是 Haiku，更不是用户常用的模型；结果落在边界上，才补一次真 Haiku（补之前先报 Master，由它问 PO）。
- 填充轮次让模型读小文件，上下文大小远小于真实长会话。
