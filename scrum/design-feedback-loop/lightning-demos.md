# Lightning Demos（工作材料）

> 2026-11-11，design-feedback-loop 的构思·发散。三个 Explore 子代理（haiku）按三个领域各找一批现成的做法；原文收在这里，供草图子代理借用、组合。工作材料，不进设计日志。

## A 个人随手记录和收集

1. **GTD 的「收集篮」（Inbox）**
   怎么做：冒出来的事不分轻重，先全部丢进一个收集篮，只在固定时间清空和分类。
   可借：把「丢进去」和「分拣」拆成两步，说出口的那一刻不需要知道它属于哪个项目。

2. **语音助手的「帮我记一下」（Siri + 备忘录、Todoist 自然语言快速添加）**
   怎么做：一句话就能触发，Siri 默认存进备忘录；Todoist 从「明天三点交周报」里自己拆出时间、项目、提醒。
   可借：落点由系统给默认值，说的人只给内容，元数据由 AI 从话里抽，不用逐项报。

3. **Drafts**
   怎么做：打开就是一张空白纸，写完再用动作把文字发去邮件、待办或笔记，自称「文字开始的地方」。
   可借：入口永远是同一张白纸，去向是写完后的一个动作，而不是开口前的选择。

4. **每日笔记（Obsidian / Logseq 的 Daily Note）**
   怎么做：所有临时想法都落在自动生成的「今天」这一页，之后再靠链接、标签或移动来整理。
   可借：让日期自动当收件箱，点按天落页、天然按时间排好，省掉「该放哪」这一问。

5. **卡片笔记的「闪念笔记」（Fleeting Notes）**
   怎么做：先随手记下不完整的念头，之后再加工成常青笔记，原始记录用完可以扔掉。
   可借：承认捕捉时只能给原料，把「写清楚」留给第二次处理，不要求一次到位。

6. **子弹笔记的快速记录 + 月度迁移（Bullet Journal）**
   怎么做：用符号几秒钟记一条，月底把没做完的条目重新抄到下个月，抄的时候决定留还是丢。
   可借：迁移本身就是复查，攒下的点会在固定节奏里被重读一遍，而不是永远沉底。

7. **AudioPen 一类语音笔记的 AI 整理**
   怎么做：对着手机说一段散乱口语，AI 转写后整理成带标题、分段、要点的文字。
   可借：允许输入是口语和错字，由 AI 负责变成后来的人读得懂的样子，顺手纠正听错的名字。

8. **Limitless Pendant（原 Rewind）这类常开记录**
   怎么做：随身设备持续记录环境里的对话和想法，事后可以搜索、回看、让 AI 总结。
   可借：不依赖「交出去」这一刻，环境本身持续留痕，没说出口的点也能事后捞回来。

## B 软件团队收集使用中的反馈

**Lightning Demos：软件团队收集「使用中的反馈」的现成做法**

1. **BugHerd / Marker.io**
   做法：在网页上点一下，评论就钉在具体元素上，自动截屏并带上浏览器、系统、分辨率等现场信息，直接进一个共享看板。
   可借：**位置和现场由产品自己产出来**，提的人只要说"这里不对"。

2. **Google 内部 dogfood 构建里的「发送反馈」**
   做法：预发布版内置反馈入口，摇一摇或菜单提交时自动附上构建号、设备型号、系统版本、截图，有时还有日志。
   可借：把"哪个版本、哪台机器、哪个界面"变成捕获时**自动长出来的字段**，不占用说话。

3. **macOS / iOS 的 Feedback Assistant**
   做法：提交反馈时自动打包 sysdiagnose（日志、配置、最近崩溃），工程侧拿到的是可复现的现场，而不是一段描述。
   可借：捕获那一下顺手抓一份"当时发生了什么"，**后来的人不必靠回忆补上下文**。

4. **Linear Asks（Slack 里一句话变 issue）**
   做法：在 Slack 消息上打一个 emoji（或私聊、或在专用频道里随便说）就生成对应团队的 issue；原帖链接跟着走，评论双向同步，统一落进 Triage 收件箱，还带查重。
   可借：**投递只要一个动作，去向由"在哪个频道、哪个项目"这类现成上下文决定**，不用人报地址。

5. **Linear Triage / Canny 一类反馈池**
   做法：所有来源的反馈先汇进一个收件箱，在里面接受、拒绝、搁置、标重复；重复的合并成一条，需求按主题聚起来看。
   可借：**先全收、后归位**；攒下的东西是"按主题的一堆"，不是"按时间的一长串"。

6. **Bug bash（微软、Google 常见的集中找 bug 活动）**
   做法：定一段时间，全员当用户把产品用一遍，当场提，事后集中分拣和修；有固定入口、固定时段。
   可借：把"随手记"**接在一个定期发生的仪式上**，收的时候有明确的起点和终点。

7. **Dogfooding 本身（"吃自己的狗粮"；Figma、Notion 等都内部先用）**
   做法：团队每天用自己最新的构建干活，遇到问题在内部频道随手说，构建和反馈在同一个地方。
   可借：让**"用的人"和"能改的人"之间只隔一个频道**，反馈不必先变成一份需求文档。

8. **GTD 的收集箱 / Drafts 这类"先捕获后决定"的习惯**
   做法：任何念头先进一个不分类的收件箱，打开就是空白输入，写完再决定它去哪、做什么。
   可借：**捕获那一秒不做任何判断和归类**，归位留到之后单独一次做。

说明：第 2、3、6 条是公开的通用做法，未当场核对文档；第 1、4 条已核对产品页。

## C AI 助手与智能体的记忆

**Lightning Demos：AI 助手与智能体的记忆**

**1. ChatGPT 的记忆（Saved memories + reference chat history）**
它怎么做：对话中自动捕捉或按你一句"记住这个"存成一条条独立的记忆条目，在设置里能逐条看、改、删；另外有一套独立的"引用历史对话"，不落成条目，用到时才召回。
可以借：记忆写成一条条可审阅的短句，而不是一整篇流水；"值得长期留着"和"用得上就临时捞回来"分成两件事。

**2. Claude Code 的 auto memory + CLAUDE.md**
它怎么做：Claude 自己判断哪些纠正和偏好值得记，写进按仓库分开的记忆里（worktree 共享），每次会话开头自动加载；CLAUDE.md 是人写的常驻说明，两者并存。
可以借：记什么由 AI 判断、记到哪个桶由工具按当前所在项目自动决定，人只需要说内容。

**3. Cline 的 Memory Bank**
它怎么做：约定一组固定的 markdown 文件（activeContext、progress、systemPatterns 等），开工先全部读一遍；说一句"update memory bank"就整轮重写、逐文件过一遍。
可以借：留一个"更新时必读"的固定入口，把平时散落的点收束到少数几处，更新时一次拿全。

**4. mem0**
它怎么做：把对话蒸馏成一条条事实、跨记忆连接实体，按 user / agent / app / run 分层存放，查询时只回最相关的几条。
可以借：落库那一刻就把口语长句压成"一条事实"，并自动去重合并，后来的人不用再读原始对话。

**5. Letta（MemGPT）**
它怎么做：记忆是 agent 能用工具自己编辑的"记忆块"，最重要的常驻在系统提示里，旧的对话即使被挤出上下文也仍留在库里可检索。
可以借：常驻一小块"最近在意的点"，其余放进可检索的档案层，两头都不丢。

**6. Granola**
它怎么做：不进会议、只在后台听电脑音频转写，你随手打几个字，它结合会议上下文扩成结构化笔记和待办；会后可以直接问"我这周答应了什么"，还能通过 MCP 把笔记交给 Claude、Cursor 等工具用。
可以借：输入可以极碎（几个关键词就够），成文由工具补全；记录本身对外开放，任何产品都能来取。

**7. Claude Code 的 hooks（UserPromptSubmit / Stop / SessionStart）**
它怎么做：在固定事件上自动跑脚本，不依赖模型的记性，也不依赖人记得说。
可以借：把"记一下"绑在"每说完一句""每次会话收尾"这类事件上，落点和格式由钩子保证，人永远不用说位置。

**8. GTD 的 capture inbox（Drafts、Things 收件箱、快捷捕捉一类习惯）**
它怎么做：所有念头先进同一个默认收件口，当场不分类、不决定去向，之后集中处理。
可以借：所有产品共用一个默认收件箱，位置问题从"每次都要说"变成"一次都不用说"。
