**测法**

- **两个会话，一个脚本**：陌生人（S）和插件会话（P）都是 claude-magpie 的便宜模型（非 Haiku）。驱动脚本在中间传话：把 S 的话当用户消息发给 P，把 P 这一轮的回答转给 S；记录两边的全部输出；控制轮数和时长；S 发出的 `ASK_AUTHOR:`、`STUCK:` 两种行只记录、不回答（回一句「作者不在，只用 README 和插件」）。
- **S 拿到什么**：陌生人卡里「是谁」一栏（译成英文）、README 和它链到的 `docs/` 里快速上手、词汇表的全文（英文版）、任务；不给「要什么、怎么算满意」，那是判卷用的。S 只说英文。
- **任务**（只写目标和要的结果，不列步骤、不带引导；步骤让 S 自己从 README 和链到的文档里找，五个产出留在判卷那边，不给 S）：一个空文件夹（不是 git 仓库），一个小产品：每天在终端里打印一句话的小工具（一个文件）。交给 S 的原话：「You want to use this plugin to plan and finish the first small Sprint for this little tool. When that is done, take a look at the project's board and say what is waiting for you now.」身份只加一句：「This is your own project. You have no particular ideas of your own; when you are asked to decide, agree to reasonable plans.」（不说出插件里的角色名：「你就是 PO」该由 README 和快速上手教会，Master 复查后改）通道只告诉它这些：你坐在项目文件夹里的 Claude Code 对话框前；以 `/` 开头的行当命令输入，其余当消息发给 Claude Code；不给它别的 shell。
- **S 怎么「看」看板**：每当 `scrum/ScrumBoard.html` 出现或改动，驱动脚本把它看得见的文字（去掉标签、脚本和样式）附在 P 的回答后面转给 S，不给源码；过线第 5 条比的，就是 S 据这段文字说出的「在等 PO 的事」和日志里的 Waiting for PO。
- **装插件**：S 先把 README 的安装命令原样发出来；驱动脚本把 GitHub 地址换成本地仓库路径，在隔离的配置目录里执行，把输出回给 S（换地址写进报告）。S 发出的命令和 README 对不上，算「同一步卡」的开始。然后驱动脚本在那个配置目录和临时项目里开 P。冒烟先验：隔离的配置目录下 magpie 的认证还管不管用；不行就退回 `--plugin-dir`，「装」这一步标成没测到。

**卡住的判定**（四条，每次都读记录判；判错的逐条人工看，改判写明理由）

1. 同一步卡两轮以上：S 连续两个来回在同一步上没有进展；
2. 会话报错或原地打转：P 返回错误或超时，或同一个工具调用连续失败三次，或 S 重复同一句；
3. S 要的信息 README 和链到的文档里找不到：S 每发一次 `ASK_AUTHOR:` 或 `STUCK:` 都算，不用另判；
4. 撞到轮数或时长上限，没走完。

卡点是文档的毛病还是模型的毛病，读记录判：重复出现（≥2 次，含跨运行），或要的信息文档里没有的，算文档的卡点；文档里本该有、只出现一次的，也算，不因次数少放过；模型自己的失误（读错、乱答、工具用错）不算，记在「模型的失误」一栏。

**过线**（数字先定，跑了之后不改）

1. 一组 3 次里至少 2 次走完（五个产出都在）；
2. 最后一组里没有文档的卡点；之前出现过的每一个，要么已修、最后一组里没再出现，要么修不了、已登记进产品日志（sprint-log 第 21 条）；
