## 冒烟校准（2026-11-23，只改取证的写法；达标线、样本量、选法没动）

冒烟 14 个会话全部跑完（并发 2，0 技术失败）：init 事件里工具只有 `Read,Grep,Glob,Skill`（子代理那个多 `Task`）、模式 `dontAsk`、模型已设、`permission_denials` 为 0，限制真生效。校准了这几处读法：

- **A 的证据在哪**：Skill 的 `tool_result` 只是「已加载」，技能正文在紧接着的一条 `user` 消息里，暗号在那条消息里；① 的证据读「Skill 调用成功后紧跟的那条 `user` 消息」。
- **② 压缩后**：压缩后日志里看不到补附了什么，证据用探针答复——压缩后最后一条 `result` 文本含 `-zq7`，且含确切的结尾暗号（摘要不会留随机串，被截断的副本也丢它）。冒烟里 A1、B、C 在约 8,000 字符下都答对；N 对照在正式测里补。
- **③ 子代理**：产出取 `Agent` 的 `tool_result`（带 `[Subagent hand-back]` 前缀），脚本在这段文字里找 `-zq7`，不看主会话自己的总结（主会话带着清单，会替子代理说）。
- **另测里的 B**：模型自己调 `ideo-scrum:developer` 时，B 的 `UserPromptExpansion` 没触发（暗号 0），印证判据里的预期；正式测里按另测的约定补一条 `PreToolUse`（matcher `Skill`）再测 3 个会话。
- **噪声**：偶发一次 `UserPromptSubmit` hook `outcome: cancelled`、退出码 1（承诺 hook，不是 Memory 的 hook，只在一个会话里出现）。记为噪声，不算 Memory 的失败；它让该会话缺证据时按技术失败补跑。
- **运行上限**：`message_s` 600、`session_s` 1500 不变（冒烟最长的会话 135 秒）。
- **并发与内存**：并发 2；冒烟期间空闲内存最低 2,019 MB（开跑时 3.2 GB）。正式测用看门狗（空闲内存连续两次 < 2,000 MB 就整棵进程树杀掉），按档、按判据分批跑，已有结果的试次下次跳过、续跑。
