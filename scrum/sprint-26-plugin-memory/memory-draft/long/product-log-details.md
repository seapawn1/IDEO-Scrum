# Product log details

Two parts of the product log whose rules are tables: writing it from a blank page, and what the seven item columns hold. Read this file when you write a product log for a product that cannot be described yet (`blank-page`), or when you add or change an item (`item-columns`).

## Blank page (`blank-page`)

Write into the product log what you can define; replace what you cannot with the matching item of a design, and let the design answer it. When the product and its Product Goal cannot be written, the IDEO methods alone will not make them clear; start from a design (the design-kernel skill), which adds the design sprint, a prototype, and a test to those methods (the boundary between the design sprint and the five modes is `sprint-or-modes`). The design's items stand in for the product log's like this:

| The design log | Product log |
| --- | --- |
| The challenge | 1.1 Product |
| The design goal | 1.2 Product Goal |
| The design questions, once the test has answered them | 1.3 Definition of Done (the Outcome Done measures); the ones not answered become items |
| The people at the top of the map | 2.1 Stakeholders |
| The map | 2.2 Map |
| The target (the design-kernel skill's `steps/2-3-pick-a-target.md`) | 3 Product Backlog Items, each placed on a step of the map |

In a section a design is answering, say which design answers it and link to it; do not copy the design log. The stakeholder table can be written first, because a design uses role cards from its first stage.

## Seven columns (`item-columns`)

| Column | What goes in it |
| --- | --- |
| # | PBI- and three digits, counting up: PBI-001, PBI-002, and so on |
| Title | A short name |
| User story | "As <someone from section 2.1>, I want …, so that …" |
| Place | A step of the map, or a subsection of section 2.2 |
| Status | Where the item stands: waiting, in Sprint NN, in a design |
| Size | S — one or two sessions; M — three to five sessions; L — more than five sessions, to be split when refining |
| Notes | Source, open points, draft acceptance criteria, refinement notes |

## Open points for the Product Owner

- The # column says "PBI- and three digits" (PBI-001); this project's own product log writes PBI-51, without the leading zero. The rule is kept word for word; the PO may want to settle which form the plugin asks for.
