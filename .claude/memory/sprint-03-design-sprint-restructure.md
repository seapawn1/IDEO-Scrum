# Sprint 03（design-sprint-restructure）蒸馏

> 源：全文 `Scrum/sprint-03-design-sprint-restructure/SprintBacklog.md`（git 历史 `v1` tag 起可查）。

**增量**：Design Sprint 全书 3750 行从单 checklist 拆为结构化体系——Monday `references/` 6 文件 + SKILL.md 重构；Tuesday 引用文件建成后回滚。

**核心发现（v2.0.0 种子）**：Monday 是**认知单元**（隐喻+原理+方法，适独立引用文件）；Tuesday-Friday 是 **workshop 操作系统**（纸笔/圆点贴纸/匿名评审——7 人×5 天×物理空间实现细节，核心概念一句话讲完）。不能统一文件化——需为 solo+AI 重新设计，此为 PBI-6→并入 PBI-7 的由来。

**教训**

1. **先拆一个样本再决定拆全部**：Monday 做完模式清晰，周二一做即暴露结构差异。
2. **引用文件 ≠ 翻译 checkboxes**：操作指令照搬仍是操作指令，不会变成方法论。
3. **原书含隐含 UI 假设"7 人一个房间"**：拆文件本质是做解耦——方法论核心与特定 UI 分离。
4. **流程步骤型 vs 认知单元型的边界**是方法论文件化工作的核心判断维度，后续结构化工作先作此分类。
5. 文件名等结构稳定后再定（monday/ → references/ 重命名）。

**遗留**：Tuesday-Friday 内容空缺（待 v2.0.0 / PBI-7 承接）。
