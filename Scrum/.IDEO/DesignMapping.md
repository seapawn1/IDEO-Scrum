## 第一部分 Design Sprint（设计冲刺）

### 1. Challenge —— 挑战宣言（整体插件）

> IDEO-Scrum 现在交付的是「给人读」的方法论文本，而方法论本身预设的是 7 人团队；真实用户却是 solo——一个人 + 一个 Claude。本插件的挑战：把方法论重塑为一个 **agent 插件**——Claude 以角色形态存在（master 教学 / designer-developers 执行），以 agent 方式跑流程（快速验证、验收联动、指路），让一个人 + Claude 顶一个团队，把 design → scrum 一条链跑通。判据：solo 用户全程少开口——Claude 自己推节奏、给约束、做验收，而不是等人逐条来查文档。
>
> （依据 define-the-challenge.md：高赌注——solo+AI 支柱全体成立与否；时间不充裕——v2.0.0 三条线并行；卡住——1.x 终点即场景错配。）

### 2. Goal

> 照抄产品愿景（ProductBacklog.md → Product Vision）：
> 让 Claude Code 成为一个随身的设计思维与敏捷教练——有方法论需求的人打开 Claude Code 调用 IDEO-Scrum，就能获得结构化、忠于原文、可操作的方法论引导。

### 3. Questions（三条脊柱，悲观换问题法，start-at-the-end）

| # | 问题 | 防的是 |
|---|---|---|
| Q1 | 一场快速验证流程能否不按五天法跑完？「完赛」的可观测信号（对话轮次/时长）是什么？ | 换皮不换骨——去掉日程表，用起来依旧三天 |
| Q2 | 去掉时间箱后，什么机制能产生收敛压力——流程闸门（HMW→Target、投票）还是预置的多 agent 一把梭？ | 发散出不来收敛，solo+AI 一路铺开无结论 |
| Q3 | 没有真人测试对象，验证结论还剩多少决策价值？AI 扮演挑剔用户的哪种证据形式，作者愿意信？ | 原型做完测了个寂寞，验证闭环断裂 |

> 注：Q4-Q6 草稿（原型性价比 / 认知单元×流程分层 / 触发入口）本轮不写——按用户意见剔除；前两条已并入 Q1-Q3 的相关性思考，后一条喂 map 起点。
